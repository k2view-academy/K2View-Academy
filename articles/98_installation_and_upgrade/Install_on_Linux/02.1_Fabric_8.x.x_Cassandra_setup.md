# Fabric with Cassandra Setup

This section describes how to configure Fabric version or later to use Cassandra as its System Database.

---

## Overview

Cassandra is well-suited for larger-scale, distributed deployments that require high availability and scalability.

> **Note:**  
> If Kafka nodes are not provided, Fabric’s PubSub component will run in in-memory mode.  
> Refer to [PubSub Configuration](/articles/24_non_DB_interfaces/02a_pubsub_config.md) for additional details.

---

## Prerequisites

The following information is required before setup:

- SystemDB type: `CASSANDRA`
- Cassandra node IP addresses (comma-separated list)
- Cassandra user and password
- Kafka node IP addresses (optional; only required for multi-node Fabric deployments)

## Version Considerations

**Python Version Note**  
 - Cassandra 3.11.14 requires **Python 2.7** for utilities like `cqlsh`.  
 - Cassandra 4.0.3 and 4.1.3 require **Python 3.6 or higher**.  

Ensure the correct Python version is installed on Fabric nodes where Cassandra tools are invoked.

**Cassandra Version Considerations**  
 - **Cassandra 3.11.14**: Uses legacy configuration (e.g., defaults in `cassandra.yaml`, standard JVM tuning).  
 - **Cassandra 4.x** (4.0.3, 4.1.3):  
   - Ensure `allocate_tokens_for_keyspace` is removed if deprecated.  
   - Validate TLS settings and SSL options, especially in multi-node clusters.  
   - Apply recommended Java 11+ JVM tuning flags where applicable.

---

## Fabric Setup Command

Run the following command on each Fabric node, replacing the placeholders with your actual environment values:

~~~bash
/opt/apps/fabric/fabric/scripts/fabric-setup.sh \
  --systemdb-type CASSANDRA \
  --systemdb-user k2admin \
  --systemdb-password changeit \
  --systemdb-host 10.0.0.1,10.0.0.2,10.0.0.3 \
  --kafka-host 10.0.0.4,10.0.0.5,10.0.0.6
~~~

> **Note:**  
> You may omit the `--kafka-host` parameter for single-node deployments.


## Post-Setup Configuration

After running the setup command:

 - Verify cqlsh connectivity using the appropriate Python version.
 - Review and tune cassandra.yaml and JVM options according to your version (see the Version Specific Notes above).
 - If using TLS, ensure the Fabric nodes can establish encrypted connections to Cassandra.

   
---

## SSL / TLS (Optional Hardening)

If your Cassandra and/or Kafka instances are configured to require SSL:

- Add the `--ssl` switch to the `fabric-setup.sh` command.
- The SSL certificates will be imported into Fabric’s truststore automatically.

~~~bash
--ssl
~~~
